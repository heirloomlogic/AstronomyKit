# Historical production source archive

This archive replays frozen diagnostic evidence after the shipping C implementation changes. The [manifest](manifest.json) pins the baseline revision `ec134360afc24f91cbc2724bd81b2a925e110194`, original source paths and SHA-256 values. The independent-reference fixture pair is retained from its measurement revision `8bf9bfff0ab2f8bf5d7bcb4befe3a21b72114a94`; those per-file revisions are explicit in the manifest. Archived files append `.archive` so they cannot become active Swift/C sources or Python test owners. All original source notices remain inside the archived bytes.

`source_archive.py` validates the tracked manifest and each archived file before use. Its baseline tree contains the original `astronomy.c`, original public header and the hash-verified polynomial, VSOP and nutation assets used by the historical source. These unchanged large generated assets remain in their original tracked paths and are validated before linkage. Live references and retained reports are linked into the temporary tree; registered historical fixture and script versions override those links with actual copied bytes. The helper preserves original relative source labels in the frozen reports and needs no kernel download or access to old Git objects.

Historical `--check` or `check` commands in the range and outer-planet tools execute the byte-pinned original scripts in that temporary tree. Historical polar and Pluto diagnostic controls read the registered original source bytes directly. Current-model measurements continue to compile the complete current C target, including the ephemeris evaluator and native ERFA time/frame units, and hash the generated `.inc` data along with C sources and headers. A historical replay proves reproduction of the archived baseline and its frozen tolerances; it does not establish acceptance of the current shipping model.
