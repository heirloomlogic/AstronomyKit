# Independent polar horizon evidence

Research date: 2026-10-03. Issue [#124](https://github.com/heirloomlogic/AstronomyKit/issues/124). The independent comparison supports retaining the current model for now: it is closer to the convention-aligned JPL horizon calculation for three of four sampled crossings, including the disputed South Pole sunrise. This is finite diagnostic evidence, not an accepted accuracy guarantee, a fully identical Earth-orientation comparison, or authority to remove the existing known failure.

## Comparison

The raw independent responses and complete query recipes are archived under [`Scripts/reference-data/sources/polar-reference`](../../Scripts/reference-data/sources/polar-reference). [`polar-reference-comparison.json`](polar-reference-comparison.json) binds every response/query pair by SHA-256, records the JPL ephemeris and Earth-orientation headers, and binds the previously compiled model event report. Both model event times are compared in TT, with JPL explicitly queried using `TIME_TYPE=TT`. The model times retain their source-bound Espenak-Meeus UT/TT conversion; JPL times are not generated by interpreting those UT labels as UTC.

The independent calculation uses JPL DE441 apparent, airless topocentric Sun-center elevations at geodetic latitude ±90°, longitude 0°, ellipsoid height zero. It solves `centerElevationDegrees + degrees(asin(695700 km / apparentRangeKm)) + 34/60 = 0`. This adopts the library's variable solar semidiameter and constant 34-arcminute sea-level refraction convention, rather than using JPL's automatic rise/set markers. Horizons quantities 4 and 20 supply the elevation and range; quantity 13 is retained as a diameter cross-check. [Horizons observer quantities](https://ssd.jpl.nasa.gov/horizons/manual.html#obsquan), [explicit time-scale and site query settings](https://ssd-api.jpl.nasa.gov/doc/horizons.html).

Signs are calculated TT minus the independently interpolated JPL TT root. The JPL reference root for the disputed sunrise is 2022-09-20 21:54:30.694 TT, corresponding to 21:53:21.510 UTC using the historical TT−UTC offset of 69.184 seconds. That UTC coordinate must not be compared directly with the archive's UT1 minute or substituted for the frozen harness's derived TT comparison. [USNO TT definition](https://aa.usno.navy.mil/faq/TT), [USNO Universal Time definition](https://aa.usno.navy.mil/faq/UT), [NIST leap-second history](https://www.nist.gov/pml/time-and-frequency-division/time-realization/leap-seconds).

The reference root uses a quadratic interpolation of three regular 30-second samples across a sign-changing bracket. The largest absolute difference between the linear and quadratic interpolations for these four matched roots is below 0.00004 second. This is an interpolation diagnostic, not a certified root-error or astronomical uncertainty bound. The two exact model event epochs are also included in each request, so the archived reference elevations independently retain the residual sign at each model event.

## Source and convention controls

Fresh USNO one-day API queries reproduce all four archived minute values: South sunset 18:07, South sunrise 21:52, North sunrise 13:02, and North sunset 04:13. Their API version is 4.0.1. The independent acquisition-provenance review establishes that the pinned fixture originally came from the USNO yearly service, whose parser copied the hour/minute fields and appended `Z` without a time-scale conversion. The current one-day response is corroboration of the archived minute, not its original acquisition source. [Source investigation and primary citations](PolarSunriseReferenceSources.md).

USNO's public explanation describes an average fixed 50-arcminute center depression, while the library uses a distance-dependent solar radius plus 34 arcminutes. Solving the fixed-50-arcminute equation against the same JPL data changes these four roots by approximately −163, −297, +232, and +227 seconds respectively, in the table's order. The disputed sunrise's fixed-threshold root is earlier than both the archived minute and the library result. Therefore a literal substitution of that abbreviated definition does not reconcile this case. The USNO yearly/one-day implementation is not exposed by that explanation, so these are convention-sensitivity controls, not proof of the source algorithm or a source defect. [USNO sunrise/set definitions](https://aa.usno.navy.mil/faq/RST_defs).

Horizons uses historical EOP corrections, measured nutation offsets and polar motion in its ITRF93 terrestrial orientation. The library uses its own precession/nutation models and an idealized equator-of-date pole. Identical numeric latitude does not remove the difference between these local verticals. JPL also documents gravitational light-deflection corrections that do not establish correction-by-correction identity with the library's Sun equatorial path. These differences remain visible in the report and prevent attribution of the remaining approximately 1.5–1.8-second current-model residuals solely to the solar coefficient set. [Horizons frame and Earth-orientation documentation](https://ssd.jpl.nasa.gov/horizons/manual.html#frames).

Actual observed sunrise has additional atmospheric, terrain and observer-height uncertainty. This work compares an idealized deterministic horizon observable and does not validate field visibility at the physical South Pole station. The USNO timestamp has minute precision and its captured yearly header does not specify the seconds-rounding rule. Neither fact permits changing the existing 70.8-second regression allowance. [USNO rise/set limitations](https://aa.usno.navy.mil/faq/RST_defs).

## Disposition supported by the evidence

Owner decision on 2026-10-03: retain the current production model after reviewing the independent polar evidence. Keep issue #124 open, preserve its archived row and known-failure assertion, and retain the unchanged 70.8-second allowance. This is an interim model-retention decision, not acceptance of the archive disagreement, a new accuracy threshold, or closure of #81.

Do not revert the solar/nutation models merely to make the archived South Pole row pass: that would make this sampled JPL comparison worse, including a much larger South Pole sunset residual. Retain the existing archive row, known-failure assertion and unchanged 70.8-second limit. Issue #124 remains open because independent agreement under the declared library-style horizon convention does not satisfy its existing archived-minute completion criterion or resolve the hidden source/model relationship.

Selecting a new accuracy acceptance policy or redefining the public sunrise observable remains an owner decision. The approved interim disposition retains the current model while preserving the unresolved archive disagreement. It does not qualify the full geographic/date domain or select limits for #81.

## Reproduction

Run `python3 Scripts/reference-data/diagnose-polar-sunrise.py --check` to recompile and verify the two models and isolated controls against the source-bound event report. Run `python3 Scripts/reference-data/investigate-polar-reference.py check` to verify the independent response/query hashes, requested epochs, location/time conventions, live-USNO corroboration snapshot and generated comparison offline. `python3 -m unittest discover -s Scripts/reference-data -p 'test_polar_reference.py' -v` checks rejection of clock/location/query corruption and mathematical interpolation controls.

`python3 Scripts/reference-data/investigate-polar-reference.py acquire` refreshes the eight independent responses sequentially from JPL/USNO; `report` regenerates the comparison. Refreshes are explicit because ephemerides, EOP versions and service output can change. The checked-in report is a frozen 2026-10-03 acquisition, not a promise that a later refresh will reproduce every digit. No production implementation, source fixture, test allowance, GitHub issue or PR is changed by this research.
