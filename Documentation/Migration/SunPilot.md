# Development native Sun pilot

Issue #83 remains open. The complete native Earth/Sun calculation path is implemented, but the frozen mixed-workload latency and throughput gate is unestablished, fixed-budget Linux RSS observations exceed the Apple baseline ceiling, and independent review remains required. These receipts do not authorize production graduation or a full Swift port.

The pilot evaluates the complete frozen Earth polynomial and compensated VSOP tables, explicit captured Delta T models, light-time backdating and stopping rules, precession, 77-term nutation, observer parallax, and geometric altitude. Its evaluator owns bounded Earth/orientation caches; immutable Earth VSOP triplets are initialized once while retaining original bit patterns, term order, and compensation expressions. Shipping `Package.swift`, coefficient sources, oracle locks, fixture values, and frozen performance evidence remain unchanged.

The [protocol](SunPilotProtocol.md) defines the regression corpus, exact diagnostic fields, fixed numerical budgets, negative control, workload, and host boundaries. Run `python3 Scripts/migration/sun_pilot.py --test` for focused Debug and Release tests, then `python3 Scripts/migration/sun_pilot.py --output .context/issue83/<new-directory>` for the full campaign. The coordinator copies the inputs into an isolated SwiftPM package and materializes `Tools/Migration/SunPilotPackage/Package.swift`; it records both the manifest hash and evaluated graph. It does not rewrite the repository manifest or relabel historical measurements.

Every campaign contains 67,240 cases per configuration: all Earth polynomial boundaries and adjacent representable values, both captured Delta T models and branch boundaries, light-time stopping transitions, full-series fallback, polar/extreme observers, signed zero, and invalid inputs. Each final platform receipt retains exact time, status, branch, and iteration agreement; every reference/candidate row is archived. Full-series amplitude perturbation by `1.000001` must fail unchanged budgets in eight fallback cases for each configuration. Parity is a frozen-engine regression result, not independent astronomical accuracy or interval certification.

The original mixed performance workload includes non-pilot planets, lunar state, Pluto, and seasons. New matched Sun workload timings measure first access separately from fresh/repeated polynomial and fallback evaluation; they do not replace original latency or throughput requirements. Fresh-process RSS probes now separate startup, fixed JSON output, polynomial and complete-series Earth evaluation, evaluator cache warm-up, each existing workload, and the aggregate workload for Swift and C. RSS reports process peak resident memory rather than allocator call counts, and differences between process peaks are not additive component sizes. Fixed build, size, and RSS observations retain the frozen absolute ceilings and explicitly identify platform/toolchain differences. The extracted compensated-add LLVM inspection detects contraction/reassociation in that expression only; it does not certify whole-engine generated code.

Numerical findings during development included an invalid-observer guard that returned `invalid-parameter` where the locked engine returns `bad-time`; the regression now checks all three observer fields with NaN and both infinities. A separate initial failed campaign is retained locally. The scalar coefficient accessor also dominated fresh fallback evaluation; immutable Earth-only triplets reduced its measured Release median from 171.2 microseconds to 52.37 microseconds on the same Apple host, with fresh initialization and repeated-cache timing recorded separately.

An initial hosted workflow failed before execution because of a pinned action SHA typo; the corrected pin matches the existing representation workflow. A subsequent shipping performance provenance failure came from changing `Package.swift` despite gating the added targets. Restoring that file byte-for-byte and isolating the pilot manifest preserves the original strict validator, candidate record, and baseline. Tracker issue #83 must remain open until its unmet gates have explicit evidence; production integration belongs to #84–86.
