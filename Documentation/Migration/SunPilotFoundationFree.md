# Foundation-free development Sun pilot

The measured development Sun runner no longer links Foundation and now checks direct record delivery. The bounded remediation for [#83](https://github.com/heirloomlogic/AstronomyKit/issues/83) preserves model expressions, coefficients and workload lifecycle. Five-trial Linux startup RSS is below the unchanged 11,182,080-byte ceiling, but aggregate Release RSS still exceeds it. The pilot remains unqualified and #83 remains open.

Conditional Darwin/Glibc imports replace Foundation in scalar math; PilotTime needs no platform import. A fixed-schema writer replaces JSONEncoder/Data/FileHandle, and POSIX CLOCK_MONOTONIC replaces DispatchTime at the existing timing boundaries. The writer sorts keys, omits absent optionals, preserves decoded finite Double and integer values, escapes strings, and rejects nonfinite numbers before writing a record. JSON text may differ from JSONEncoder. Foundation remains only in serialization tests and the intentional Foundation-only RSS positive control.

Independent review found that the first Foundation-free output path used buffered, unchecked `print`: completed sample rows disappeared when later malformed input terminated the process, and a closed stdout descriptor returned success across measured modes. Test-first subprocess regressions reproduced both faults against the pre-fix receipt-bound Release binary. The corrected path uses direct checked POSIX writes, advances across partial writes, retries EINTR and fails on zero progress or other write errors. A completed record is delivered before reading the next input.

Ten focused Sun tests and five model-data tests pass in Debug and Release on Apple and hosted Linux. Three additional actual-binary regressions run in each configuration: one and ten completed rows survive later malformed input, closed stdout fails across sample/performance/all twelve RSS modes, and a 1,000-row stream delivers every record. Unit controls force partial writes, EINTR, write failure and zero progress. Each campaign report binds successful output regressions to the measured binary hash. Existing serialization controls cover omitted fields, status errors, signed zero, finite/integer extremes, escaping, deterministic output and nonfinite rejection; clock controls cover ranges, overflow and nondecreasing reads.
