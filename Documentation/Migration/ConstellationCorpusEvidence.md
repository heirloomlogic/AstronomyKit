# Source-bound constellation corpus

This investigation prepares finite legacy migration evidence for [#91](https://github.com/heirloomlogic/AstronomyKit/issues/91). It retains all 357 ordered boundary records, all 88 source name mappings, and current-public representatives for each mapping. Ordinary SwiftPM Debug does not exactly match the locked oracle on the transformed boundary samples. A separate comparison with the oracle's C compiler flags does match. Neither result establishes independent physical accuracy or a compatibility requirement for a future native implementation. Native constellation and fixed-star work remains gated by [#89](https://github.com/heirloomlogic/AstronomyKit/issues/89); #91 stays open.

The prospective protocol was committed at `046388c2a0072bd40fb6956587d5178e2595b4a0`, before collection. Its baseline is reviewed PR139 at `2d54fd251a36e94f14324daed6d0937fc250d364`. The source oracle remains `cdb533dbe85c76b39a958ca92f9155d8bd55b392` with the existing `Tools/Migration/Oracle/oracle-lock.json`; its upstream Astronomy Engine revision is `826e26ff3a6dc03ee46658b1138fef582d96c5d9`. The locked and current constellation table, initialization, and lookup text are identical. Full source MIT/vendor notices accompany the archived text. Source spelling is preserved, including index 1's `Antila`; this is a source mapping inventory, not an independent audit of official names.

## Selection and frames

Mathematical table-space tests use the source's compact units: 360 units per RA hour and 24 units per declination degree. The first matching record wins. Declination and RA lower edges are inclusive; the RA upper edge is exclusive. Each of the 357 records has 21 directed probes: both RA edges with their exact and adjacent binary64 values crossed with the three declination-lower-edge values, plus its RA midpoint crossed with those declination values. Expected ownership is the first matching row, which can precede the row whose edge is being probed. All 7,497 probes remain in the archive, including 148 outside the spherical input domain.

Each model's public-input partition contains 7,479 requests: one initialization anchor, 7,349 valid-domain table probes, 88 deterministic representatives, 33 direct RA-wrap/pole controls, and eight invalid-input controls. No failing request was discarded. The separate parsing control covers 7,471 non-invalid requests; its eight-request exclusion is the invalid-input partition, including two finite declinations just outside the allowed range. All eight invalid controls still execute in every full public comparison.

The 88 representatives use source-record RA midpoints and declination midpoints below the nearest earlier covering record's higher threshold. The first source-owned candidate for each index is selected without failure tuning. Both supported models' archived current-public outputs cover all 88 source mappings.

Transformed public inputs are J2000 equatorial RA hours and declination degrees. Their decimal tokens were acquired once from the locked C inverse of the legacy rotation and are replayed unchanged. The legacy initialization uses UT days `-45655.74141261017` from J2000, `Astronomy_TimeFromDays`, and `Astronomy_Rotation_EQJ_EQD`, with the process-global Delta-T function active at first initialization. This names the source's date-frame convention; it does not certify that convention as an independent realization of physical constellation boundaries. `Constellation.find` accepts `Double` directly, with no `Angle` conversion. C and Swift parse every non-invalid archived input to identical binary64 bits.

Mathematical table identities and transformed public identities are separate observations. Inverse rotation, spherical conversion, and forward rotation can move a nominal tie across an edge. Each model retains 1,691 table/public identity differences, including 72 valid transformed nominal-boundary requests returning `internal-error`. The replay retains those errors and permits recorded cross-platform categorical/status changes only in the transformed table-boundary partition. Interior representatives and direct controls require unchanged identity/status. Coordinate comparisons reuse the existing platform regression envelope of `1e-8` degree, with RA scaled to hours; it is not a physical uncertainty bound.

## Observed build conditions

The original archive compares the frozen oracle's C build (`-O3`, `-DNDEBUG`, `-fno-fast-math`, `-ffp-contract=off`, and its other locked flags) against a development runner using ordinary SwiftPM Debug C settings. It contains 38 mismatching input results per initial/post-model pair, including eight categorical mismatches. Across four pairs this is 152 mismatch observations and 32 categorical observations, not 152 or 32 unique cases. Every original output and mismatch remains unchanged.

A second development-only build applies the entire locked C flag set to the isolated current-public runner. It reuses every original input and retains separate output/build receipts. All four pairs have zero exact parsed-result differences between locked C and current public APIs. This is a compound build-condition diagnostic: several compiler settings changed together, so the experiment does not identify a unique flag or arithmetic contraction as the cause. Production package settings and sources are unchanged. Ordinary Debug remains a recorded negative exact-parity result.

Both supported Delta-T models coincide at the legacy initialization epoch: the JPL Horizons approximation delegates to Espenak/Meeus before its post-2017 clamp. All four initial/post-model pairs show unchanged initialized lookup results. Separate fresh processes exercise 32 concurrent cold workers on four anchors, compare their 128 ordered results with serial initialization, and compare C with current public APIs. These controls do not test a custom Delta-T function that differs at the initialization epoch or general concurrent model mutation.

## Authentication and replay

`Tools/Migration/ConstellationResearch/Artifacts/` holds the original source text, parsed tables with coefficient bits, complete case/input selection, build receipt, compressed outputs, assessment, and manifest. Its manifest SHA-256 is `a6beefcf6881cebef3cea797dbe8166b15c7b2a06f1e79ff544b06d6b000110d`. `AcquisitionTools/` retains the exact tool source texts authenticated by that manifest. The original assessment's `representativesPerModel` was computed from locked C; current-public coverage is independently verified by the matched derivation and replay.

`DerivedEvidence/` holds the separate matched-build outputs and assessment. Its manifest SHA-256 is `e1d6ce033b6c9421f54e59b9f1f78b74bb6c1dfef41a37133494408925c30ad2`; it binds the original manifest and frozen protocol. `DerivationTools/` preserves the tool texts used for this diagnostic. `validation-provenance.json` declares the current offline validator and binds it to the unchanged derivation. Its current-tool hash can change when the validator is repaired; both measured manifests exclude this file. Historical validator states remain in Git, and neither measured archive is rewritten. Manifest verification checks file population and raw hashes before semantic validation; equality of two detached or empty streams cannot establish a complete result set. All three tool maps and both three-file snapshot directories require exact populations. Historical tool identities are bound to their recorded hashes. Required build fields validate the oracle revision/source closure, adapter, public manifest and ordinary-Debug versus matched flag conditions. Historical compiler/platform/binary identifiers bind their archived receipt; rebuilt identifiers are checked against the actual current build, allowing a different platform or compiler.

Run `python3 -m unittest Scripts/migration/test_constellation_corpus.py -v` and `python3 Scripts/migration/constellation-corpus.py check`. The checker authenticates both archives and tool provenance, rebuilds the locked C and isolated current-public runners, verifies source selection and inverse-frame relationships, and replays all public and cold-start requests in fresh processes. It detects actual C mutations of table order (7,289 differing probes), exclusive RA lower comparison (1,447), inclusive RA upper comparison (1,049), name substitution (7,349), and identity-frame substitution (7,437 transformed inputs). Python controls also reject detached, missing, duplicated, reordered, nonfinite, wrong-name/status, inconsistent-coordinate, and rehashed-empty payloads. This is finite source-bound evidence, separate from the frozen migration corpus and its acceptance gates.

Local Apple replay, 17 Python control tests, isolated runner lint with generated Persnicket configuration, contract inventory, package build, and all 713 package tests passed with the suite's existing known issue. Hosted Linux/macOS replay is a separate validation boundary until its jobs pass. No native implementation, star-slot change, oracle lock, production source, dependency prerequisite, or accuracy target is changed by this investigation.
