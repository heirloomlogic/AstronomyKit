The corpus also contains a broad light-time stopping-count scan with adjacent times, fallback epochs near the accepted-date extremes, polar observers, negative/high elevations, signed zero, and invalid inputs. ## Foundation-free dependency remediation

The development runner uses conditional Darwin/Glibc scalar math, Swift standard-library output and a fixed-schema JSON writer. It preserves omitted optional fields, statuses, decoded finite Double values (including signed zero), integer precision and JSON escaping; nonfinite output throws before writing a record. JSON text need not match JSONEncoder byte-for-byte. Tests compare decoded values against JSONEncoder and reject NaN/infinity. Codable protocols remain in the Swift standard library; Foundation is used only by tests and the intentional Foundation-only RSS positive control.

The workload clock is POSIX CLOCK_MONOTONIC, converted to UInt64 nanoseconds with checked range and overflow. Timing starts and stops at the same workload boundaries. Counts, epoch sequence, checksum expression and evaluator lifetimes remain unchanged. This changes the clock implementation, so fresh measurements retain their own host/toolchain receipts.

Fresh RSS reports use schema version 3 and name the current candidate control `pilotRunner`; archived schema version 2 reports retain `unchangedRunner`. Mapping validation requires Foundation on the positive control and rejects Foundation mappings on the minimal, model-linked and candidate controls. The original ceiling and historical evidence remain unchanged.
