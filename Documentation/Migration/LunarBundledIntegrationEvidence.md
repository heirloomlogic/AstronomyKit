# Bundled lunar integration evidence

AstronomyKit's lunar integration uses one immutable Float64 coefficient array compiled into `CLibAstronomy`. The [source manifest](LunarBundledSources/moon-de440.manifest.json) binds the official DE440s kernel, generator, native time/frame sources, generated include, coefficient bytes, units, frame, centers, coverage and notices. The array represents geometric Moon center `301` minus Earth center `399`; no Earth-Moon barycenter approximation, light-time or aberration is folded into the coefficients. Runtime evaluation requires no external file, network, CSPICE installation or model selection flag.

The [generator](../../Scripts/ephemeris/generate-lunar-bundle.py) subtracts matching type-2 Chebyshev coefficients from `(3,301)` and `(3,399)` in the original byte-pinned official kernel. It preserves all thirteen coefficients on each axis, converts kilometers to AU using exactly 149597870.7 km/AU, and emits hexadecimal C floating literals that round-trip to the generated Float64 values. All 823,329 compiled coefficients, including exterior guards, match the separately loaded original SPK coefficients after the specified subtraction and AU conversion. The array occupies 6,586,632 bytes before executable/linker overhead; its 19,586,727-byte source text is not installation size, process RSS or measured runtime allocation.

The integration contract uses DE440 throughout `[1900-01-01,2131-01-01)` TT, Julian dates `[2415020.5,2499391.5)`. Physical TDB guards run from JD 2414986.5 to 2499425.5, with coefficient grid start JD 2414984.5, 21,111 four-day records, and thirteen coefficients per axis. These guards support a 32-day exterior transition to the existing lunar model. The production evaluator owns that transition and its position/velocity derivatives. The public date domain remains unchanged; this finite qualification does not establish accuracy of the transition margins or of the existing model farther outside the required interval.

ICRF/ICRS source axes are converted to the existing mean equatorial J2000 output contract using the official ERFA `eraPmat06(2451545,0)` frame-bias matrix. The same constant rotation applies to position and velocity. Native TT-to-TDB conversion uses the full official `eraDtdb` periodic geocentric model with split dates `(2451545,TT offset)` and zero topocentric observer coordinates. “Full” refers to the retained routine and periodic terms; the geocentric TDB-TT model remains an approximation, as its official documentation states. The analytic coefficient derivative is AU per TDB day. `Astronomy_EphemerisTDBRate` supplies dTDB/dTT from a symmetric 0.01-TT-day difference of the periodic correction so the public velocity is AU per TT day. Native time values and all three frame-matrix columns match the separately loaded pinned Python ERFA reference in the local controls; in-place vector transformation is also covered.

The original 6,581,696-byte `MOONDEV1` payload is regenerated as a proof artifact with SHA-256 `a1921ec68223515ce97bea46d6db171329ddba8219c349f4c4b0d2ecce81f89c`. It is not shipped alongside the C array. This preserves the coefficient identity of the [frozen native probe](native-lunar-candidate-probe.json) and [fresh holdout](lunar-candidate-holdout-assessment.json). The archived native holdout replay again matched all 128 positions and all 52 events: 27 apsides and 25 nodes, with zero exceedances or identity failures. Its maximum angular error is 0.000131635 arcminute, maximum absolute range error is 0.00260450 ppm, and maximum absolute timing errors are 0.0119492 second for apsides and 0.0116274 second for nodes. Those are finite DE440-versus-Horizons comparisons under the original frozen limits and one-second engineering event allowance; they are not physical covariance or continuous-domain guarantees. A byte-identical coefficient slice and passing native time/frame controls do not by themselves prove public API correction behavior or event searches.

The [derived-data notice](LunarBundledSources/moon-NOTICE.txt) identifies Heirloom Logic as the modifier and NASA/JPL as the original source producer. The [unmodified kernel comments](LunarBundledSources/moon-de440-source-comments.txt) retain original source provenance and the DE440/DE441 publication attribution. The official [NAIF rules](https://naif.jpl.nasa.gov/naif/rules.html) govern the original materials and distinguish modified kernel attribution. The derived array is named separately and is not an official JPL SPK kernel. Eight unmodified ERFA C routines and their two headers are byte-bound to ERFA 2.0.1 commit `9915ba38c9365f8b0738269b8c2ac1fdd5f8dee3`; each retains its official notices, and the full [ERFA license](LunarBundledSources/ERFA-LICENSE) is retained outside the C build target. The local wrapper is separate from those official routines.

Verification commands are `python3 Scripts/ephemeris/generate-lunar-bundle.py --check` for checkout-only integrity using the Python standard library, `python3 Scripts/ephemeris/generate-lunar-bundle.py check` for exact reproduction from the pinned original kernel and reference packages, `python3 -m unittest discover -s Scripts/ephemeris -p 'test_*.py'` for generator/native controls, and `python3 Scripts/reference-data/qualify-lunar-candidate-holdout.py check` for archived native holdout replay. `generate --proof-payload --output <scratch>` emits the original binary proof in a custom directory; default generation emits only the compiled data and provenance files. Neither integrity mode downloads source data.

Final bundle verification passed the five lunar generator/native controls, checkout-only integrity, exact original-kernel regeneration and archived 128-position/52-event holdout replay. The complete reference-data Python discovery passed 101 tests with zero failures or errors. Historical polar, Pluto, apparent-range, 2,546-case distance and 5,035-case range-rate replays also pass after separating original baseline inputs from current production sources. The [historical archive](../../Scripts/reference-data/sources/production-baseline/README.md) retains source revision identity, including the original apparent-range fixture revision, and leaves frozen reports, hashes and tolerances unchanged. Current-model C probes link the complete ephemeris/time implementation and include generated coefficient data in their input hashes. The negative held-out control intentionally exercises and rejects a one-case failure; its printed failure is covered by a passing test.

Public API integration and current-model qualification are recorded in [Bundled ephemeris integration](BundledEphemerisIntegration.md) and the [public API assessment](bundled-public-api-assessment-v2.json). The bundle controls above establish source, serialization and native time/frame identity; public correction behavior, event searches, transition derivatives, concurrency, platform costs and acceptance claims belong to that integrated evidence and its stated limits. No historical replay is relabeled as current-model acceptance.
