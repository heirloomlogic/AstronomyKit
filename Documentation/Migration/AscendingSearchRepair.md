# Ascending search repair

`Search.findRoot` documents a negative-to-nonnegative crossing. The inherited C solver could return a descending interpolated root or a midpoint in a short constant window. Both reported public failures reproduced under Espenak–Meeus and JPL Horizons before repair; the retained pre-fix test run recorded 100 failed assertions across the direction/constant matrix and exact reports.

Both success paths now require endpoint callback signs that establish an ascending bracket, with at least one strict sign. Quadratic acceptance also requires a positive fitted derivative; that derivative does not substitute for callback evidence. An unbracketed outer interval still evaluates its midpoint and can select an ascending subinterval. The existing single-root assumption remains; these tests do not promise discovery of every crossing in a window containing several roots. Tolerance arithmetic, captured Delta-T propagation, callback errors and the iteration limit remain unchanged.

The caller inventory covers all 17 direct invocations: solar longitude, elongation, lunar phase, horizon searches, peak magnitude, lunar and planetary apsides, eclipse shadow minima and contacts, transit boundaries and lunar nodes. Descending physical contacts are sign-normalized before the generic ascending solver. Some shadow searches assume a bracket inside a fixed window; this inspection does not prove their physical completeness.
